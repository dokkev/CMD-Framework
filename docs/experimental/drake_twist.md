# Drake 쥔 원기둥 비틀기 (39차, 실험용, Study 3 본 실험 아님)

새 목표의 둘째 후보다. pull-out(21차)의 쥐기 그대로에서 하중 대신 원기둥 자기 축에 대한 torque를 올려, 쥐기가 풀리는 torque를 잰다(회전 pull-out). 접선 방향 접촉 경로를 시험한다. 결과는 report/에 넣지 않는다.

## 39차 사전 기록 (2026-11-25, O만으로 보정, R·U는 gate만 확인, 재설계 손의 D와 E를 보기 전)

### 구현 (`sim/drake/twist_grasp.py`)

- 21차의 닫기, 안정화, Gate 0(`preload_match.pull_settle`, 조건 A, setpoint q0 + 5°, point contact, K_Q 5)을 그대로 쓴다.
- 안정화된 상태에서 원기둥 spin에 torque를 손가락 하나당 0.01/3 N·m/s로 올린다. 사건은 slip(pad 접선 속도 > 10 mm/s), loss(pad 법선력 < 0.2/3 N), collapse(중심이 5 mm 움직임), 30° 넘게 돎 중 첫째다.
- 한계 torque는 F_limit처럼 손가락 셋 몫(×3)으로 적는다. 방향은 +spin(distal pad 쪽 면이 손끝 쪽으로 감)과 −spin이고, 각각 안정화된 상태에서 가른다.
- `two_pad_drake.Stage`를 상속해 torque만 적용 힘에 더했다. `two_pad_drake.py`는 고치지 않았다.
- **배치:** ρ 12.5, 15, 17.5, 20 mm × q0 80–115°(5° 간격) = 32개, two_pad_grasps 규칙. ρ 15·20은 21차의 배치와 같다.
- **지표:** D = τ_limit(μ 2.0) − τ_limit(μ 1.3), 쌍은 (ρ, q0, 방향)이다. E(H) = |D(H) − D(O)| / |D(O)|의 중앙값.

### O만의 보정 (이 기록 전)

- ρ 15·20만(16개 배치)이면 28쌍이었다. 40쌍을 넘기려고 ρ 12.5·17.5를 더했다.
- **최종 O (tag e39):** Gate 0 28/32, solver 0, 관통 최대 0.70 mm. 사건은 loss 96, slip 18이다.
  - **56쌍.** 제외는 Gate 0 실패 8이고, |D(O)| 바닥(torque 3 step)에 걸린 것은 없다.
  - **D(O) +0.0067 / +0.0163 / +0.0273 N·m, 모두 양수.** 바닥의 20–80 step이라 양자화가 작다.
- **잡음 바닥 (O 명령 +0.05°, tag e39n):** 중앙 **0.00%**, 75분위 **1.93%**(56쌍).
- **R·U gate 확인:** R Gate 0 24/32, 관통 최대 0.48 mm. U Gate 0 27/32, 관통 최대 1.52 mm.

### 지표와 판정 (사전, 38차와 같은 형식)

- **E(H):** O의 56쌍 중 H가 두 μ 모두 Gate 0을 지나고 안정화 관통 ≤ 1.5 mm이고 한계가 있는 쌍. 실패는 따로 세고 무한대 민감도를 보고한다.
- **판정 1:** E_R < E_U(5, 9 mm 쌍도). **판정 2:** ρ(E, Δ_contact) > 0, 순열 p < 0.05(2만 번, seed 0, 단측). **판정 3:** ρ(E, Δ_skel)을 비교한다.
- **궤적:** 원기둥이 돈 각(0–10°)까지 버틴 최대 torque의 편차, R − O와 U − O, μ 1.3·2.0. 최대와 끝을 보고한다.
- **해석:** 판정 1·2가 성립하면 회전 방향의 하중에서도 오차가 Δ_contact를 따른다.

### 순서

이 기록을 커밋한 뒤 나머지 16개 손을 worker 6으로 돌린다(손 셋에 76 s; 약 7분). 렌더는 손바닥 위 power-grasp 카메라로 세 손가락이 원기둥을 쥐고, 원기둥 끝면에 회전 화살표를 그린다.
