# Drake 손끝으로 멈춤쇠에 기대 상자 세우기 (35차, 실험용, Study 3 본 실험 아님)

사용자 요청: 논문에 좋은 새 과제를 골라 끝까지 돌린다. 결과가 접촉면 운동으로 정해지고, 그림이 pull-out, 원판, 동전과 다른 과제여야 한다. 결과는 report/에 넣지 않는다. 데이터는 `sim/drake/logs`에 둔다.

**고른 과제와 이유.** 후보는 셋이었다.
1. 멈춤쇠에 기대 상자 세우기: 외부 접촉을 쓰는 비파지 조작.
2. 경첩 레버 누르기: Study 3에서 뺀 28y 평면 다이얼과 비슷하다.
3. 쥐기 전에 손끝으로 물건 밀어 넣기: 23차 획득과 겹친다.

1을 골랐다. 손끝이 상자 윗면을 손바닥 쪽으로 끌고, 탁자 위 멈춤쇠가 상자의 손바닥 쪽 아래 모서리를 막아 상자가 기운다. 기운 각은 pad가 윗면에서 붙느냐 미끄러지느냐, 즉 손끝 접촉점이 상자 위에서 움직이는 경로가 정한다. 그림(기우는 블록)도 기존 세 과제와 다르다.

## 35차 사전 기록 (2026-11-25, O만으로 보정, R·U는 gate만 확인, 재설계 손의 D와 E를 보기 전)

### 구현 (`sim/drake/box_pivot.py`, 그림 `sim/drake/render_pivot.py`)

- 평면 CoDe 검지(`two_pad_drake.py`의 기하, servo 표, 조건 A의 임피던스를 읽기만 함). MCP 0에 고정, 손바닥이 아래를 보고 중력 있음(동전 끌기와 같은 틀). point contact, pad 2.5 kN/m, time step 0.25 ms.
- **탁자:** 수직 스프링 60 N/m(감쇠 2 N·s/m) 위의 판이다. 자신과 블록의 무게는 일정한 힘이 받친다. 누르는 힘은 스프링이 정한다(동전과 같다). 탁자 위에 **멈춤쇠**(높이 3 mm, 폭 6 mm)가 블록의 손바닥 쪽 면 아래에 닿아 있다.
- **블록 (폭 w, 높이 h, 질량 M, 깊이 30 mm):** 아래 모서리의 구 발(반지름 0.5 mm) 넷으로 탁자에 놓인다. 평평한 면끼리의 point contact는 퇴화하므로 구 발을 썼다(30차와 같은 이유).
  - x, z로 움직이고 y축으로 기울 수 있다. 중심에 **비틀림 복원 스프링 k_r**(감쇠 2e-4 N·m·s/rad)이 있다. 스프링이 없으면 pad가 늘 붙어 기운 각이 μ와 무관하다(끈 없는 동전과 같다).
  - 블록–탁자 μ 0.5. pad–블록 μ는 1.3 또는 2.0이다.
- **배치 (O에서, proximal-face 좌표, 모든 손에 같음):** 블록 윗면은 O의 손끝 면 점이 q_t에서 있는 깊이에 둔다. 블록의 손끝 쪽 모서리는 그 점에서 edge_mm 앞이다.
- **명령 (조건 A, O의 열린 루프):** 굽힘 0 → q_t(1 s) → q_t + sweep(3 s), 유지 1 s. 이득은 q_t에서.
- **측정:**
  - **주 지표: 끝의 기운 각**(°, 윗면이 손바닥 쪽으로 가면 +). D = tilt(μ 2.0) − tilt(μ 1.3).
  - **보조 지표: 최대 기운 각**(같은 D 정의). 보고만 하고 판정에는 쓰지 않는다.
- **lost (과제 실패):** pad가 닿지 않음, 끝의 pad 법선력 < 0.0667 N, 기운 각이 45°를 넘음(넘어짐), 또는 피벗 모서리가 멈춤쇠를 떠남(손바닥 쪽으로 1 mm 넘게 미끄러짐, 또는 탁자에서 멈춤쇠 높이 넘게 들림). 관통은 pad 법선력 최대 / 2.5 N/mm다.

### 뽑기 (seed 35, 64개, `logs/pivot_e35.json`)

`numpy.random.default_rng([35, 35])`에서 이 순서로 균등 벡터를 뽑는다. 모든 손이 같은 뽑기를 쓴다.
- q_t 25–40°
- w 18–26 mm, h 14–22 mm
- edge 2–5 mm
- sweep 20–30°
- k_r 0.02–0.04 N·m/rad
- M 20–40 g

### O만의 보정 (이 기록 전)

- **처음 12개:** 기운 각(μ 1.3) 1–14°, μ 2.0에서 10–20°, D 5.4–9.5°, 관통 ≤ 0.40 mm. lost 규칙의 "멈춤쇠를 넘음"을 처음에는 블록 중심 이동으로 쟀다. 중심은 모서리를 축으로 기울기만 해도 2–3 mm 움직이므로(6/12를 잘못 lost로 셈), 피벗 모서리의 탁자 기준 위치로 바꿨다. 그 뒤 lost 0/12다.
- **최종 O (64개):**
  - solver 0, lost 0, proximal 접촉 0, pad–탁자 접촉 0, 관통 최대 0.66 mm(중앙 0.29).
  - 피벗 모서리는 멈춤쇠에서 0–1.0 mm 손끝 쪽으로 움직인다.
  - 기운 각(μ 1.3) 0.0 / 6.2 / 17.5°, μ 2.0에서 1.3 / 12.0 / 23.4°(최소/중앙/최대).
  - **제외는 |D(O)| < 0.3° 1개뿐이고 63개가 남는다.** D(O) −7.88 / 6.31 / 9.76°.
  - 음수 4개(draw 16, 30, 43, 48)는 μ 2.0에서 블록이 더 기울었다가(최대 14–21°) 끝에 pad가 미끄러져 스프링이 되돌린 경우다. 실제 사건이므로 주 지표에 그대로 둔다. 보조 지표(최대 기운 각)에서는 64개 모두 남고 D 1.95–10.12°로 모두 양수다.
- **잡음 바닥 (O, 명령 +0.05°, tag e35n):** 주 지표 중앙 **0.52%**, 75분위 **0.94%**(63쌍). 보조 지표 0.50 / 0.89%.
- **time step:** 0.25 vs 0.125 ms에서 D 차이는 중앙 0.53%, 75분위 1.56%, 최대 7.6%(16개).
- **R·U gate 확인 (D, E는 보지 않음):**
  - R: solver 0, lost 0, proximal 0, pad–탁자 0, 관통 최대 1.57 mm(1개 > 1.5)
  - U: 모두 0, 관통 최대 0.67 mm
- **그림:** O, draw 26(D 6.35°, μ 1.3 끝 기울기 8.2°). sweep 시작, 기울기가 끝 값의 절반에 처음 닿는 때, 끝. 검지만 굽히고 가운데·약지는 접었다. 동전 열의 카메라. 블록의 시작 윤곽과 빨간 회전 화살표를 그렸다(`logs/render_pivot{0,1,2}.png`, `logs/render_pivot_strip.png`).

### 지표와 판정 (사전, 30b·33·34차와 같은 형식)

- **E(H):** O의 63개 뽑기 중 H가 lost 아니고 관통 ≤ 1.5 mm인 쌍에서 |D(H) − D(O)| / |D(O)|의 중앙값(주 지표).
  - H의 lost, over-pressed, solver 실패는 따로 세고 뺀다. 무한대로 둔 민감도를 보고한다.
  - proximal과 pad–탁자 접촉은 점수에 넣고 센다.
- **판정 1:** E_R < E_U. 5, 9 mm 쌍도 보고한다.
- **판정 2:** ρ(E, Δ_contact) > 0이고 순열 p < 0.05(손 18개, 2만 번, seed 0, 단측).
- **판정 3:** ρ(E, Δ_skel)을 보고하고 비교한다.
- **궤적:** 블록 기운 각 대 sweep 시작부터의 시간. R − O와 U − O의 중앙값과 사분위(μ 1.3, 2.0; fig4_sync deviation과 같은 구조). 최대와 끝을 보고한다.
- **보조:** 최대 기운 각으로 같은 E와 ρ(판정에 쓰지 않음).
- **해석:** 판정 1·2가 성립하면 외부 접촉을 쓰는 비파지 조작에서도 재설계 오차가 Δ_contact를 따른다. 지표가 안정하고 gate가 유효한데 성립하지 않으면 그대로 보고한다.

### 순서와 계산

이 기록을 커밋한 뒤 나머지 16개 손을 worker 6으로 돌린다(손 둘에 169 s, 합계 약 23분 예상). 보정 wall time: 12개 15 s × 2, O 64개 82 s, 잡음 약 80 s, time step 비교 약 60 s, R·U 169 s, 렌더 약 1분.

### 명령

```
cd sim/drake
uv run python box_pivot.py draws --out logs/pivot_e35.json
uv run python box_pivot.py run --hands O --draws logs/pivot_e35.json --tag e35
uv run python box_pivot.py run --hands O --draws logs/pivot_e35.json --tag e35n --delta_deg 0.05
uv run python box_pivot.py run --hands R U ... --draws logs/pivot_e35.json --tag e35
uv run python box_pivot.py analyze --tag e35 --noise_tag e35n --out logs/e35_pivot.json [--metric tilt_max_deg]
uv run python box_pivot.py frames --draws logs/pivot_e35.json --draw 26 && uv run python render_pivot.py --draw 26
```
